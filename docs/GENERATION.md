# 자료 생성 지침 (매일 08:45)

앱은 **읽기 전용 정적 사이트**입니다. 매일 아침 자동 작업이 아래 파일을 만들어 GitHub에 올리면, Cloudflare Pages가 자동 배포하고 앱이 그 파일을 읽습니다. API 키·서버·DB 없이 무료로 동작합니다.

```
08:45 자동 작업
  ① 광둥어 / 영어 / 중국어를 각각 따로 생성
  ② 언어별로 따로 검증 (아래 체크리스트)
  ③ data/days/YYYY-MM-DD.json 저장
  ④ node tools/validate.mjs        ← 형식 검사
  ⑤ node tools/build-index.mjs     ← data/index.json 갱신 (검증 실패 시 앱에 "생성 실패" 표시)
  ⑥ git add data && git commit && git push   → Cloudflare Pages 자동 배포
```

시작할 때 `node tools/build-index.mjs --generating YYYY-MM-DD "생성 중"` 을 먼저 push 하면 앱에 "생성 중"이 보입니다.
실패하면 `--failed YYYY-MM-DD "원인"` 으로 표시하세요. 파일이 없고 index에도 없는 날은 "자료 없음"입니다.

## 파일 형식 — `data/days/YYYY-MM-DD.json`

[examples/2026-10-02.example.json](../examples/2026-10-02.example.json) 참고. 필드:

| 필드 | 설명 |
|---|---|
| `id` | `yue-1`…`yue-5`, `en-1`…`en-10`, `zh-1`…`zh-10` (그날 안에서 고유, 진행 기록의 키) |
| `word` | 단어 |
| `reading` | 발음 (언어별 표기는 아래) |
| `meaning` | 한국어 뜻 |
| `pos` | (선택) 품사 |
| `example` | 그 단어가 들어간 짧은 예문 1개 |
| `exampleReading` | (선택) 예문 발음. 광둥어·중국어는 넣는 것을 권장 |
| `exampleKo` | 예문의 한국어 번역 |

> ⚠️ 한 번 올린 날짜의 파일을 나중에 고쳐 다시 올리면 `id`는 유지하세요. 완료 기록이 `날짜|id` 로 저장됩니다.

`data/config.json` — 개수·수준·주제. 앱 설정 화면의 "config.json 내용 복사"로 바꾼 값을 여기에 반영하면 다음 생성부터 적용됩니다.

## 광둥어와 표준중국어를 섞지 않기 — 생성 · 검증을 분리

두 언어는 **서로 다른 프롬프트, 서로 다른 검증**을 씁니다. 한 번의 호출로 둘을 같이 만들지 마세요.

### 광둥어 (yue) 생성 지침
- 홍콩 광둥어 **구어체**. 표기는 **번체**.
- 발음은 **Jyutping + 성조 숫자 1–6**, 음절 사이 공백 (`zou2 san4`).
- 예문은 실제 광둥어 구어 어휘·문법: `係` `唔` `冇` `咗` `嘅` `佢` `我哋` `呢/嗰` `啲` `乜嘢` `點解` 등.
  **표준중국어를 광둥어 글자로 옮기는 식(書面語)으로 쓰지 말 것.** 예) ✗ 我不是學生 → ✓ 我唔係學生
- `meaning`에 구어/표준어 차이가 있으면 한 줄로 짚기 (예: 唔該 = 부탁/감사/실례).

### 광둥어 검증 체크리스트 (생성한 모델과 별도 호출로 수행)
1. 단어·예문이 번체인가? 간체가 섞이지 않았나?
2. Jyutping 음절 수가 한자 수와 맞고 성조 숫자가 모두 있나?
3. 예문에 `是 不 沒有 什麼 我們 他們 了` 같은 **표준중국어 표현**이 없나? 있으면 광둥어 표현으로 교체
4. 홍콩 사람이 실제로 말할 문장인가? 어색하면 교체
5. 한국어 뜻·번역이 정확한가?

### 표준중국어 (zh) 생성 지침
- **간체**, 발음은 **성조 부호가 있는 병음** (`zǎocān`, 경성은 부호 없음). 성조 숫자(`zao3`) 금지.
- 예문은 자연스러운 보통화 구어. 광둥어 글자(`嘅 唔 係 咗 冇 佢 啲 嘢 哋`)·어휘 금지.

### 표준중국어 검증 체크리스트
1. 단어·예문이 간체인가? 번체가 섞이지 않았나?
2. 병음에 성조 부호가 맞게 붙었나? 숫자가 없나?
3. 광둥어 표현이 섞이지 않았나?
4. 한국어 뜻·번역이 정확한가?

### 영어 (en)
- 발음은 `/…/` 안의 IPA. 예문은 일상 회화체, 단어(또는 변화형)가 문장에 들어갈 것.

### 공통
- 수준: 설정의 값(기본 초급~중급), 주제: 설정의 값(기본 실생활).
- 같은 날 단어 중복 금지. 최근 날짜에 나온 단어와도 겹치지 않게 하면 좋습니다.

## 자동 검사기가 잡는 것

`tools/validate.mjs`는 위 체크리스트 중 기계적으로 잡을 수 있는 부분(간체/번체 혼용, Jyutping·병음 형식, 광둥어 글자가 중국어에 섞임, 개수, 필수 필드, 한국어 번역 존재 등)을 검사합니다. 휴리스틱이라 **의미·자연스러움은 위의 별도 검증 단계가 담당**합니다. 오류가 있으면 앱에는 "생성 실패"로 표시되어 잘못된 자료가 학습 화면에 나가지 않습니다.
